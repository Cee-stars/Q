# 復習キュー (Fukushu-Queue)

溜めた学習項目を、**忘れかけた頃だけ**出す復習アプリ。
時間を決めて回し、来たら途中でも止める。残りは翌日にまわる。

`https://cee-stars.github.io/Q/`

---

## 作り

外のライブラリは使わない。バニラJSのみ。パスは全部相対なので、
サブディレクトリ配信でそのまま動く。

```
index.html            本体（画面・SRS・読み上げ・入出力）
sw.js                 オフライン用
manifest.webmanifest  アイコンは base64 で埋め込み
```

保存は IndexedDB `fukushu-queue`。

| store | 中身 |
|---|---|
| `items` | 学習項目（keyPath `id`） |
| `meta` | `days` … その日にやった件数。連続日数の集計に使う |

設定は `localStorage` の `fq.settings.v1`（制限時間・読み上げ速度・声・最後のモード）。

### service worker と単一ファイルについて

当初の仕様は「単一 index.html」だったが、**Service Worker は独立した
ファイルとして同一オリジンから配信される必要がある**。`register()` は
Blob URL も data: URL も受け付けない。オフライン動作を取るために 3 ファイル
構成にしてある。

manifest も実ファイルにした。Blob URL の manifest は `start_url` が
`blob:` 基準で解決されて scope が壊れるため、ホーム画面追加で問題が出る。
アイコンだけは仕様どおり base64 埋め込み。

## 用語について

Leitner の 1〜5 と、項目をまとめる入れ物の両方を「箱」と呼ぶと二重になるので、
分けてある。

- **ボックス** … 利用者が作る入れ物（My Dictionary / 瞬間英作文 / 自作）
- **レベル1〜5** … 間隔反復の段階

コード上のフィールド名は `item.box`（レベル）と `item.boxId`（ボックス）。
`item.box` を改名すると既存のデータの移行が要るので、表示だけを変えてある。

---

## ボックス

項目をまとめる入れ物。どのボックスを回すかを選んでセッションを始められる。

```js
box = { id, name, color, order, createdAt, updatedAt }
item.boxId = "<box の id>" | null    // null は未分類
```

IndexedDB は version 2。`boxes` ストア（keyPath `id`）が増えている。

### 移行（1 度だけ）

`meta.boxMigrated` が立っていなければ実行する。`sourceApp` を手がかりに振り分ける。

| `sourceApp` | 行き先 |
|---|---|
| `My Dictionary` | 同名のボックスを作って割り当て |
| `瞬間英作文` | 同上 |
| `Grammer-dict` | 同上 |
| それ以外（`manual` / `csv` / 空 / 未知の値） | 未分類 |

**印は書き込みが成功したあとにだけ立てる。** 途中で落ちても項目には触らず、
次に開いたときにやり直す。2 回走っても結果は変わらない。

### 同じ名前のボックスは 1 つに寄せる

2 台がそれぞれ手元で移行すると、同じ「My Dictionary」でも **id の違う
ボックスが 2 つ**できる。id で突き合わせる限り両方残ってしまうので、
同期のたびに名前を鍵にして寄せる。古いほう（`createdAt` が早い、同着なら
`id` が小さい）を残し、指している項目を付け替え、消えたほうに墓標を残す。

手で作るときも、同じ名前は作れない。取り込みの行き先が名前で決まらなく
なるため。

### 移行前の端末から届いた項目

同期で来た項目が `boxId` を持っていないとき、問答無用で未分類に落とすと、
こちらの移行はもう済んでいて二度と走らないので、`sourceApp` があっても
永久に取り残される。移行と同じ振り分けをかけてから倒す。

### 書き出し → 仕分け → 読み込み

自分の書き出し（`boxes` と `boxId` が入っているもの）を読み込むときは、
行き先を聞かずに**ボックスごと復元する**。向こうの id はこちらの id に
読み替え、足りないボックスは作り、同じ名前があればそれを使う。

仕分けを人手や別の手で済ませて、ファイルで戻す渡し方ができる。
1 件ずつ画面で直すのが大変なとき用の逃げ道。

### まとめて移す

一覧の「まとめて移す」で選んで、いくつでも一度に移せる。その場で新しい
ボックスを作って入れることもできる。

未分類に溜まったものを分けたいときに、1 件ずつ開いて直すのは数があると
つらい。「未分類で絞る → 表示中をぜんぶ選ぶ → 移す」で片づく。

### 削除

ボックスを消すときは、中の項目をどうするか必ず聞く。

- **未分類にする**（既定）… 項目は残る
- **項目ごと消す** … 項目にも墓標を残して消す

黙って消すことはしない。同期でボックスが消えたときも、それを指していた項目は
未分類に倒れる。宙ぶらりんにしない。

## データモデル

```js
item = {
  id, japanese, english, note,
  sourceApp,        // 取り込み元。手で足したら "manual"、CSV なら "csv"
  box,              // 1〜5
  nextDue,          // "YYYY-MM-DD"
  createdAt, lastReviewedAt
}
```

日付は端末の「その人の今日」で数える。UTC に寄せると日付が 1 日ずれる。

## 間隔反復（Leitner）

| レベル | 次に出るまで |
|---|---|
| 1 | 1 日 |
| 2 | 3 日 |
| 3 | 7 日 |
| 4 | 14 日 |
| 5 | 30 日 |

- **言えた** → レベルを +1（5 で頭打ち）
- **詰まった** → レベル 1 に戻す
- 出すのは `nextDue <= 今日` のものだけ

**繰り越しは何もしなくても成立する。** やり残した項目は `nextDue` を
触らないので、翌日そのまま対象に残る。

1 項目につき 1 セッションで 1 回だけ採点する。同じセッション中に
同じ項目が戻ってくることはない。

## 出題モード

開始時に選ぶ。選んだものは次回に引き継がれる。

| モード | 問い | 答え |
|---|---|---|
| 日本語 → 英語 | 日本語を表示 | 英語を表示 |
| 音声のみ | 日本語を読み上げ | 英語を読み上げ＋表示 |
| 英語 → 日本語 | 英文を表示 | 日本語を表示 |
| 英語音声のみ | 英語を読み上げ | 英文を表示＋もう一度読み上げ |

読み上げは `SpeechSynthesis`。声は設定で選べる（端末が持っているものから）。
読み上げが返ってこない端末があるので、文の長さから見当をつけて必ず次に進む。

## 時間固定

- セッション開始時に制限時間を決める（既定 15 分）
- 画面上部に**残り時間と残り件数を常時表示**。残り 3 分で黄、1 分で赤
- 時間が来たら自動で終了し「今日はここまで。○件」と出す
- 未消化分は翌日にまわる（上記のとおり自動）
- 終わったあと「もう少し続ける」で延長もできる

## 入出力

- **手で追加・編集・削除**（一覧から項目を押すと編集）
- **JSON 書き出し / 読み込み** — レベルと次回の日も入るので、別の端末で
  続きから回せる。同じ `id` と、同じ「日本語と英語の組」は入れ直さない
- **他のアプリの書き出しも読める** — キーがアプリごとに違うだけで、
  中身は同じ「日本語と英語の対」なので読み替えて入れる。
  ファイルを手で渡す道なので、どこかを勝手に覗きに行ったりはしない

  | 書き出し元 | 見分け方 | どう入るか |
  |---|---|---|
  | My Dictionary | 配列の要素に `en` | `en`→英語、`ja`→日本語、例文はメモへ |
  | Grammer-dict | 配列の要素に `h` | 言い切りの形（`f`）か例文を英語に。見出しはメモへ |
  | 瞬間英作文 | `app:"sunkan"` | 自作セットと、アプリ内で足した文。**収録セットの文は書き出しに入らないので取れない** |
  | BOOKSHELF | 要素に `title` と `text` | 本そのもので対になっていないため、断って入れない |
- **CSV 読み込み** — 「日本語,英語[,メモ]」。BOM・引用符・引用符内の
  カンマ・空行に耐える。1 行目が見出しらしければ読み飛ばす

## 同期（GitHub のシークレット Gist）

サーバを持たないので、置き場を Gist に借りる。トークンは `gist` だけの
権限で足り、この端末の `localStorage` にしか置かない。

同期するのは**このアプリの持ちものぜんぶ** — 項目・ボックス・レベル・次回の日・記録・墓標。
項目はこのアプリ自身のデータなので、丸ごとやり取りしてよい。

`localStorage` の `fq.sync.*`（token / gistId / auto / last）、
Gist 内のファイル名は `fukushu-queue.json`。

### 突き合わせ

| | 鍵 | 勝つほう |
|---|---|---|
| 項目 | `id` | `lastReviewedAt`（無ければ `createdAt`）が新しいほう |
| ボックス | `id` | `updatedAt` が新しいほう |
| 記録 | 日付 | 多いほう |
| 墓標 | `id` | 新しいほう |

ボックスにも墓標（`boxTombs`）があり、消したものは連れ戻さない。

**消したものは墓標を残す。** 残さないと、向こうに居る同じ項目が同期で
戻ってくる。消したあとに向こうで触っていれば、そちらを採る。
墓標は 90 日で片づける。

記録を「多いほう」にしているのは、足し合わせると同じ同期を 2 回した
だけで二重に増えるため。2 台で同じ日にやると少なめに出るが、
勝手に増えるよりましと考えた。

自動 ON のときは、採点・追加・取り込みの 4 秒後にまとめて 1 回送る。
画面を離れるときにも送り残しを片づける。

### 壊さないための決まり

- 向こうの JSON が読めないときは、**上書きせずに中止**する。
  空として扱うと、壊れている向こうを自分の中身で塗りつぶしてしまう
- 1MB を超えると `content` が途中で切られて返る。切られたと言われた
  ファイルが空で返ってきたら、これも中止する
- 通信の失敗は手元の中身に触らない。理由をそのまま出すだけ

## 画面

- **ホーム** … 今日の件数、連続日数、ボックスの絞り込み、レベルの分布、モード選択、時間選択
- **セッション** … 残り時間と件数、問い、こたえ、2 択の採点
- **一覧** … ボックスとレベルの絞り込み、検索、項目の編集
- **設定** … 制限時間、読み上げ速度と声、書き出し/読み込み、全消去

キーボードでも操作できる。`Space`/`Enter` でこたえ、`1` 詰まった、`2` 言えた。

---

## 古い画面が開いたままのとき

IndexedDB の版を上げるとき、古い版を掴んだタブやホーム画面のアプリが
残っていると、upgrade は止まったまま `onsuccess` も `onerror` も来ない。
放っておくと約束が永久に決まらず、**画面が真っ白のまま何も出ない**。

`onblocked` を拾って理由を出す。「別のタブかホーム画面のアプリを閉じて
から開き直してください」「中身は無事です」と伝える。逆に、あとから別の
タブが版を上げようとしたら `onversionchange` でこちらは道を空ける。

---

## 更新について

ホーム画面に追加したアプリは、いちど掴んだ版をなかなか手放さない。
起動のたびと画面に戻るたびに新しい版を見に行き、入れ替わったら
一度だけ読み直す。設定の一番下に版と「最新に入れ替える」がある。
