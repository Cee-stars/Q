# 復習キュー

各アプリに散らばった学習項目を 1 本のキューにまとめ、忘れそうな頃に、
**同じ素材を複数のモードで**出題する。

覚えた項目がアプリごとに閉じていると、「一度触れたけど復習されないまま消えていく項目」が
溜まっていく。My Dictionary に入れた表現はそのアプリを開いたときしか目に入らないし、
瞬間英作文で詰まった文は次にその問題に当たるまで放置される。
それを一箇所に集めて、間隔反復で出し直すのがこのアプリ。

`https://cee-stars.github.io/Q/` — 他のアプリと同じオリジンのパス違いに置く。
これが成立の前提になっている（後述）。

## 拾ってくるもの

| アプリ | 手元から | Gist から | 拾う対象 |
|---|---|---|---|
| My Dictionary | `localStorage` `mydict.v1` | `mydict-data.json` | 登録した表現すべて |
| 瞬間英作文 | `localStorage` `sunkan:stars` / `sunkan:decks` / `sunkan:added`<br>収録分は `../sunkan-333/assets/data.js` | `sunkan-data.json` | **★を付けた文だけ**（＝詰まった文） |
| BOOKSHELF | `IndexedDB` `bookshelf` / store `books` | `index.json` ＋ `b-<id>.json` | 本文に引いた**ハイライト**の範囲 |
| Grammer-dict | `localStorage` `grammar-dict-user-v1` | **なし**（同期機能が無い） | 自分で足した構文 |

手元と Gist の両方を読んで合流させる。両方にあるものは手元を優先し、
片方にしか無いものは足す。`uid` が `ソース:元のid` なので、重なりは自然に潰れる。

読むだけ。元のアプリのデータは書き換えない。
このアプリが持つのは **予定（いつ出すか）と、書き足した訳** だけ。

### 実装にあたって分かったこと

当初「各アプリの IndexedDB から吸い上げる」つもりだったが、実物は違った。

- **IndexedDB を使っているのは BOOKSHELF だけ。** ほか 3 つは `localStorage`。
  どちらもオリジン単位なので横断で読めるが、読み方が違うのでアダプタを分けてある。
- **BOOKSHELF に「抜いた単語」という置き場は存在しない。**
  あるのは本文（`text`）と、その上のハイライト（`marks`）だけ。
  なので `marks` の範囲から語を切り出している。位置を合わせるため、
  向こうの `splitParts()` をそのまま移植してある（ここがずれると別の文字を指す）。
  **訳が元データに無い**ので、初回は「意味を書き足す」札として出し、
  訳が入ってから通常の出題に回る。
- 瞬間英作文の ★ は `{デッキid: [項目id]}` で、項目 id はデッキ内容から
  その場で組み立てられている。★ を引き当てるため、向こうの `buildRecords()` と
  同じ順・同じ `hashString()` で id を再現している。

## 出題モード

同じ素材を、入口を変えて何度も通す。どの入口が使えるかは素材が決める。

| モード | 出るもの | 答えるもの |
|---|---|---|
| 産出 | 日本語 | 英語で言う |
| 認識 | 英文 | 意味を確認 |
| 音声 | 音だけ（読み上げ） | 意味を答える |

予定はモードごとに別々に持つ（`uid|mode`）。同じ文でも「産出はまだ出てこないが
認識はできる」ということが起きるので、面ごとに間隔を伸ばす。

### 新しいものの入れ方

- 初めての素材は **その日 1 モードだけ**。同じ日に同じ文を 3 回見ても意味が薄い。
- 翌日以降、その素材の残りのモードが順に入ってくる。
- 新規枠の 6 割までを「すでに回している素材の別モード」に充て、残りは新顔に空ける。
  補完を優先しきると、手持ちが多いときに新しい素材がいつまでも入ってこないため。

10 日ほどで、入れた素材が 3 面とも回るようになる。

## 間隔反復

SM-2 を刈り込んだもの。厳密な再現率より、**まちがえた札がすぐ戻ってくること**を優先。

| 押したもの | 次 |
|---|---|
| もう一度 | 間隔を 0 に畳んで、その日のうちに再投入（5 枚ほど後ろ） |
| むずかしい | 間隔 × 1.2、ease −0.15 |
| できた | 1 日 → 3 日 → 間隔 × ease |
| かんたん | 間隔 × ease × 1.3、ease +0.15 |

ease は 1.3〜3.0 に収める。ずっと「できた」なら 1 → 3 → 8 → 20 → 50 → 125 日。

## 同期

GitHub の**シークレット Gist** に置く。他のアプリと同じ流儀。

同期するのは、このアプリの持ちもの＝**予定・書き足した訳・記録**の 3 つだけ。
**札そのものは同期しない。** 札は取り込みのたびに各アプリから作り直されるもので、
両側で足し引きすると「元で消したのに復活する」が起きる。
別の端末では、先に元のアプリ側を同期してから取り込めばよい。

置き場は My Dictionary と同じ Gist の、別ファイル（`revq-data.json`）。
Gist の PATCH は渡したファイルだけを触るので、互いの書き込みを踏まない。
瞬間英作文の `sunkan-data.json` にも「My Dictionary と同じ Gist に同居できるよう
名前を分ける」とある。1 つの Gist にアプリごとのファイルを置くのが既定の流儀。

BOOKSHELF だけは自分の Gist を使う。同じ Gist なら何もしなくてよい。
別なら設定シートの「BOOKSHELF の Gist ID」に入れる。

### 設定がいらない場合がある

起動時、自分の設定が無くて `mydict.sync.token` と `mydict.sync.gistId` が
localStorage にあれば、そのまま相乗りして**自動同期を ON にする**。
同じ端末の同じ localStorage にあるので、トークンを入れ直してもらう理由が無い。

My Dictionary 側が未設定なら、設定シートでトークンを入れて「Gistを作る」。

### 突き合わせ

| | 鍵 | 勝つほう |
|---|---|---|
| 予定 | `uid\|mode` | `last`（最後にやった時刻）が新しいほう |
| 書き足した訳 | `uid` | `glossAt`（書いた時刻）が新しいほう |
| 記録 | `ts` | 時刻がそのまま鍵なので足すだけ。直近 5000 件まで |

自動 ON のときは、採点や書き足しの 3 秒後にまとめて 1 回送る。
画面を離れるときにも送り残しを片づける。

### 壊さないための決まり

- 向こうの JSON が読めないときは、**上書きせずに中止**する。
  空として扱うと、壊れている向こうを自分のデータで塗りつぶしてしまう。
- Gist の API は 1MB を超えると `content` を途中で切って返す。
  切られたと言われたファイルが空で返ってきたら、これも中止する。
- 通信の失敗は手元のデータに触らない。理由をそのまま出すだけ。

## 気をつける点

**iOS はホーム画面に追加したアプリ・Safari・アプリ内ブラウザで保存領域が分かれる。**
別の側から見ると、各アプリの `localStorage` / `IndexedDB` は丸ごと空に見える。
リンクをタップしてアプリ内ブラウザで開いた場合も、そこは別の入れ物になる。
My Dictionary が瞬間英作文へ渡すときに URL や Gist を経由しているのはこのため。

直し方は 2 つ。

1. **項目を入れたのと同じ側から、このアプリも開く。**
2. **同期を設定する。** そうすると取り込みも Gist から読むようになり、
   ネットワーク越しなので入れ物の分かれ目を越えられる。
   どの入れ物から開いても中身が出る。

ただし **Grammer-dict は同期を持たない**ので、1 の方法でしか読めない。

そのうえで、

- 「前は取れていたのに今回 0 件」を消滅と受け取らない。その取り込みは丸ごと見送り、
  「読めず」とだけ出す。空に見えただけで札を消してしまわないため。
- 予定と書き足した訳も Gist 経由で両方の入れ物に届く。
  同期を使わない場合は、書き出し / 読み込み（JSON）でも移せる。
  どちらも、同じ面については **last が新しいほう**を残す。

## 構成

単一 HTML の PWA。ビルドなし。他のアプリと同じ作り。

```
index.html            本体（画面・アダプタ・間隔反復）
manifest.webmanifest
sw.js                 本体だけをキャッシュ。取り込み元は毎回その場で読む
```

保存先は自前の IndexedDB `revq`。

| store | 中身 |
|---|---|
| `cards` | 取り込んだ札（`uid` = `ソース:元のid`） |
| `gloss` | 書き足した訳（`uid` ごと）。札とは別に持つ |
| `srs` | 予定（`uid|mode` ごと） |
| `log` | 採点の記録（記録タブの集計に使う） |

書き足した訳を札の中に持たせると、取り込みのたびに作り直される札や、元のアプリから
消えた札の巻き添えになる。訳はこちらの持ちものなので、別のストアに分けてある。

設定は `localStorage` の `revq.settings.v1`。同期の設定は `revq.sync.*`
（トークンはこの端末にだけ置かれる）。
