# 復習キュー

各アプリに散らばった学習項目を 1 本のキューにまとめ、忘れそうな頃に、
**同じ素材を複数のモードで**出題する。

覚えた項目がアプリごとに閉じていると、「一度触れたけど復習されないまま消えていく項目」が
溜まっていく。My Dictionary に入れた表現はそのアプリを開いたときしか目に入らないし、
瞬間英作文で詰まった文は次にその問題に当たるまで放置される。
それを一箇所に集めて、間隔反復で出し直すのがこのアプリ。

`https://cee-stars.github.io/Q/` — 他のアプリと同じオリジンのパス違いに置く。
これが成立の前提になっている（後述）。

---

## 拾ってくるもの

| アプリ | 実際の保存先 | 拾う対象 |
|---|---|---|
| My Dictionary | `localStorage` `mydict.v1` | 登録した表現すべて |
| 瞬間英作文 | `localStorage` `sunkan:stars` ＋ `sunkan:decks` / `sunkan:added` ／ 収録分は `../sunkan-333/assets/data.js` | **★を付けた文だけ**（＝詰まった文） |
| BOOKSHELF | `IndexedDB` `bookshelf` / store `books` | 本文に引いた**ハイライト**の範囲 |
| Grammer-dict | `localStorage` `grammar-dict-user-v1` | 自分で足した構文 |

読むだけ。元のアプリのデータは書き換えない。
このアプリが持つのは **予定（いつ出すか）と、書き足した訳** だけ。

### 実装にあたって分かったこと

当初「各アプリの IndexedDB から吸い上げる」つもりだったが、実物は違った。

- **IndexedDB を使っているのは BOOKSHELF だけ。** ほか 3 つは `localStorage`。
  どちらもオリジン単位なので横断で読めるが、読み方が違うのでアダプタを分けてある。
- **BOOKSHELF に「抜いた単語」という置き場は存在しない。**
  あるのは本文（`text`）と、その上のハイライト（`marks`）だけ。
  なので `marks` の範囲から語を切り出している。位置を合わせるため、
  向こうの `splitParts()` をそのまま移植してある（ここがずれると別の文字を指す）。
  **訳が元データに無い**ので、初回は「意味を書き足す」札として出し、
  訳が入ってから通常の出題に回る。
- 瞬間英作文の ★ は `{デッキid: [項目id]}` で、項目 id はデッキ内容から
  その場で組み立てられている。★ を引き当てるため、向こうの `buildRecords()` と
  同じ順・同じ `hashString()` で id を再現している。

## 出題モード

同じ素材を、入口を変えて何度も通す。どの入口が使えるかは素材が決める。

| モード | 出るもの | 答えるもの |
|---|---|---|
| 産出 | 日本語 | 英語で言う |
| 認識 | 英文 | 意味を確認 |
| 音声 | 音だけ（読み上げ） | 意味を答える |

予定はモードごとに別々に持つ（`uid|mode`）。同じ文でも「産出はまだ出てこないが
認識はできる」ということが起きるので、面ごとに間隔を伸ばす。

### 新しいものの入れ方

- 初めての素材は **その日 1 モードだけ**。同じ日に同じ文を 3 回見ても意味が薄い。
- 翌日以降、その素材の残りのモードが順に入ってくる。
- 新規枠の 6 割までを「すでに回している素材の別モード」に充て、残りは新顔に空ける。
  補完を優先しきると、手持ちが多いときに新しい素材がいつまでも入ってこないため。

10 日ほどで、入れた素材が 3 面とも回るようになる。

## 間隔反復

SM-2 を刈り込んだもの。厳密な再現率より、**まちがえた札がすぐ戻ってくること**を優先。

| 押したもの | 次 |
|---|---|
| もう一度 | 間隔を 0 に畳んで、その日のうちに再投入（5 枚ほど後ろ） |
| むずかしい | 間隔 × 1.2、ease −0.15 |
| できた | 1 日 → 3 日 → 間隔 × ease |
| かんたん | 間隔 × ease × 1.3、ease +0.15 |

ease は 1.3〜3.0 に収める。ずっと「できた」なら 1 → 3 → 8 → 20 → 50 → 125 日。

## DAILY REPS との関係

DAILY REPS は「やったかどうか」の記録。復習キューは「何を出すか」の中身。
役割が違うので両方あってよい。こちらは DAILY REPS のデータには触れない。

## 気をつける点

**iOS はホーム画面に追加したアプリとブラウザで保存領域が分かれる。**
片方から見ると、もう片方の `localStorage` / `IndexedDB` は丸ごと空に見える。
My Dictionary が瞬間英作文へ渡すときに URL や Gist を経由しているのはこのため。

このアプリでも同じことが起きるので、

- **項目を入れたのと同じ側から、このアプリも開く**必要がある。
- 「前は取れていたのに今回 0 件」を消滅と受け取らない。その取り込みは丸ごと見送り、
  「読めず」とだけ出す。空に見えただけで札を消してしまわないため。
- 予定と書き足した訳は書き出し / 読み込み（JSON）で移せる。
  読み込みは、同じ面については **last が新しいほう**を残す。

## 構成

単一 HTML の PWA。ビルドなし。他のアプリと同じ作り。

```
index.html            本体（画面・アダプタ・間隔反復）
manifest.webmanifest
sw.js                 本体だけをキャッシュ。取り込み元は毎回その場で読む
```

保存先は自前の IndexedDB `revq`。

| store | 中身 |
|---|---|
| `cards` | 取り込んだ札（`uid` = `ソース:元のid`）＋書き足した訳 |
| `srs` | 予定（`uid|mode` ごと） |
| `log` | 採点の記録（記録タブの集計に使う） |

設定は `localStorage` の `revq.settings.v1`。
